## Plan: Webhook ingestion service — receive → validate → transform → persist → notify, end to end

**Authority:** Your request: service receives vendor events, validates, transforms, writes to DB, notifies downstream consumers.

**Requirement map** (locators from your request, no source IDs):
| Obligation (locator) | Step | Test | Status |
|---|---|---|---|

**Steps:**

1. **impl:S1 — Walking skeleton.** Real HTTP endpoint → hardcoded-secret signature check → minimal transform (field rename) → real DB insert → real HTTP POST to one downstream consumer. Every seam does its real job, primitive form.
   - Files: `src/server.ts` (endpoint), `src/persist.ts` (raw SQL/ORM insert), `src/notify.ts` (consumer POST), `db/migrations/001_events.sql` (single `events` table), one smoke test.
   - Test: end-to-end smoke — POST a realistic vendor-shaped payload, assert 2xx, row in DB, consumer stub received notification. Edge: duplicate POST still 2xx (accepts, no crash).
   - Ripples: none (greenfield).

2. **impl:S2 — Real vendor authentication.** [after S1] Replace hardcoded secret with the vendor's actual scheme (HMAC signature + timestamp check per their docs — spike the docs first).
   - Files: `src/auth.ts`, config/env for the signing secret.
   - Test: boundary — accept correctly signed payload; reject unsigned, tampered, expired-timestamp (401, no DB write).
   - Ripples: secrets deployment (env/secret manager).

3. **impl:S3 — Real validation + transformation.** [after S1, parallel with S2] Validate against the vendor's actual event schema (event type allowlist, required fields, size cap); transform to internal shape.
   - Files: `src/validate.ts`, `src/transform.ts`, schema definitions per event type.
   - Test: table-driven unit tests — accept each supported event type; reject malformed, unknown type, missing required fields, oversize body (4xx, never 5xx).
   - Ripples: S1's primitive transform deleted.

4. **impl:S4 — Idempotent persistence.** [after S2, S3] Vendor retries are real; dedupe on vendor event ID (unique constraint + upsert-or-ignore). Handle out-of-order timestamps if the vendor doesn't guarantee ordering.
   - Files: migration on `events` (unique index on vendor event ID), `src/persist.ts`.
   - Test: deliver same event ID twice with different payloads → one row; concurrent duplicate delivery → one row.
   - Ripples: none beyond S1's insert path. **ONE-WAY-adjacent:** unique index on live table — rollback note: drop index, revert to plain insert; kill if vendor reuses event IDs across retries with mutated payloads (confirm in docs first).

5. **impl:S5 — Durable downstream notification.** [after S4] Replace inline notify with transactional outbox: notify write committed with the event row; background worker delivers to consumers with retry + backoff, dead-letter after N attempts.
   - Files: `db/migrations/002_outbox.sql`, `src/outbox-worker.ts`, `src/notify.ts` rework.
   - Test: consumer returns 500 → retried with backoff until success; consumer down permanently → event lands in dead-letter; crash between persist and notify → worker picks it up (no lost notifications).
   - Ripples: S1's inline notify removed; deployment gains a worker process.

6. **impl:S6 — Operability.** [after S5] Structured logs with vendor event ID on every path, health endpoint, metrics (received/accepted/rejected/delivered/failed counters).
   - Files: logging middleware, `src/health.ts`, metrics registry.
   - Test: integration — rejected delivery increments rejected counter and appears in logs; health endpoint 200.
